Scope: SPEC §7.1, the production HTTP and WebSocket entry points, authentication and session services, outbound and GitHub webhooks, uploads, markdown, MCP HTTP, and the dependency and Git-history scans. This review covers the source tree at the R1 handoff; it is not a penetration test.

## CodeQL default setup (2026-10-10)

Code scanning was enabled with the default JavaScript and TypeScript query suite. Its first analysis reported six `high` alerts. Each was read at its source and dispositioned; none require a code change before release.

| Alert | Finding | Disposition |
| --- | --- | --- |
| `js/insufficient-password-hash` | `packages/services/src/lib/crypto.ts:23` — password from `generateApiKey`, `extractApiKey` and `apiKey` is hashed insecurely. | False positive. Personal API keys are stored as Argon2id hashes: `packages/services/src/api-keys.ts` writes `keyHash: await hashSecret(key)` and `packages/services/src/auth.ts` verifies with `verifySecret`. The `sha256Hex(key)` call the query follows is the in-process cache index that keeps Argon2 to one run per key per TTL, as `auth.ts` documents. Session, invite and CLI tokens are random 128-bit values and use SHA-256 as their stored hash, which is the right choice at that entropy. |
| `js/unvalidated-dynamic-method-call` | `packages/services/src/github.ts` — invocation of a method with a user-controlled name. | By design, and closed (2026-10-11). `HANDLED[input.event]?.(payload.action)` dispatches from a fixed six-entry table, and an HMAC-SHA256 signature over the raw body is verified before this line, so only the holder of the webhook secret can reach it. `HANDLED` being an object literal, an inherited key resolved through the prototype: `constructor` enqueued the event as `pending` instead of `ignored`, and `__proto__` threw. The dispatch now requires an own key (`Object.hasOwn`). `packages/services/test/db/github.test.ts` asserts `ignored` for `repository`, `workflow_run`, `constructor`, `toString` and `__proto__`; on the pre-fix source it dies on `expected 'accepted' to be 'ignored'`. |
| `js/xss-through-dom` | `packages/ui/src/components/Avatar.tsx:47` — DOM text reinterpreted as HTML. | False positive. The value reaches an `<img src>` attribute through JSX, which React escapes; there is no `dangerouslySetInnerHTML` and no DOM insertion. A `javascript:` URL in an `<img>` does not execute, and a script inside an SVG loaded through `<img>` does not run. |
| `js/polynomial-redos` | `packages/mcp-tools/src/executor.ts:32` and `packages/importers/src/client.ts:28` — regex on uncontrolled data. | False positive in practice. The expression is `url.replace(/\/+$/, '')`, where `url` is operator configuration rather than request input. Trailing-slash trimming is not reachable with attacker-controlled strings. |
| `js/polynomial-redos` | `packages/importers/src/util.ts:40` — regex on uncontrolled data. | Real but negligible. `parseDate` strips an optional trailing `(Zone name)` with `/\s*\([^)]*\)\s*$/` before `Date.parse`, and a title made of many parentheses makes that scan quadratic. The input is the operator's own import file and the work is bounded by its size, so it slows one import without crossing a trust boundary. |

The 2026-10-11 analysis of the pull request that carries the fixes below reported one new alert, `js/insufficient-password-hash` on `apps/server/src/http/mcp.ts`, where the session map stored a SHA-256 fingerprint of the API key it was created with. It is resolved by removing the flow instead of dismissing it: the map holds the key and compares it in constant time (the low finding above records why).

## Controls reviewed

- **Sessions and CSRF:** Session tokens are random 128-bit values stored as SHA-256 hashes. Cookies are `HttpOnly` for the session, `SameSite=Lax`, and `Secure` when `APP_URL` is HTTPS. Cookie-authenticated HTTP POSTs require the session's CSRF token in `X-CSRF-Token`; WebSocket sessions require the configured app origin and now carry subscriptions only. Passwords and API keys use Argon2id; revocation clears the in-process caches. Password changes revoke other sessions. Login has a per-IP-plus-account progressive delay.
- **API keys and rate limits:** Key resolution checks expiration, revocation, suspension, and deletion before returning an actor. Scope enforcement occurs in service permissions. HTTP has per-member/key token buckets and a stricter credential-endpoint bucket; limits are per process as documented in `docs/architecture.md`.
- **Outbound webhooks:** Registration and delivery reject private, loopback, reserved, and mixed public/private DNS answers unless the explicit private-target option is enabled. Delivery now pins the validated address, signs the payload with HMAC-SHA256, limits the payload and timeout, and does not follow redirects.
- **Uploads:** The allowlist, size cap, magic-byte checks for images/PDF/ZIP, image re-encoding for PNG/JPEG/WebP, and optional ClamAV path were inspected. The scanner fails uploads closed when configured and unavailable. GIF and video are not re-encoded; ClamAV remains optional, so deployments without it do not have malware scanning.
- **Markdown:** Server sanitization escapes raw HTML and neutralizes unsafe destinations. Browser rendering also uses DOMPurify. The SPA CSP allows same-origin scripts, nonce-bearing styles, and no object embedding or framing.
- **GitHub intake:** The receiver checks HMAC-SHA256 against the raw body before parsing or enqueueing, limits body size, and deduplicates delivery IDs. GitHub app credentials are read from the environment; installation tokens are minted per call. Outbound webhook secrets are encrypted using AES-256-GCM under an app-secret-derived key.
- **MCP HTTP:** The route is enabled by default (`MCP_HTTP_ENABLED=0` disables it) and requires a personal API key. When `MCP_HTTP_TOKEN` is set it is also required as the bearer token. Sessions bind to that key and tools execute through the GraphQL auth and service-permission path.
